# 产品需求文档（PRD）

## 背景与问题

同一批虚拟商品在 Google、iOS 与网页渠道中使用不同文件结构、国家命名和价格表达。人工汇总耗时且容易错档、错币种或覆盖历史数据。

## 用户与目标

主要用户为发行、商业化、运营与本地化价格管理人员。工具需要让用户在本机完成文件导入、自动标准化、问题检查、统一查询和版本留存。

## Phase1 功能

1. 选择渠道并导入 Excel 文件。
2. 用渠道 Adapter 解析国家、币种、商品/档位与价格。
3. 转换为统一价格记录。
4. 展示统计、阻断错误与警告。
5. 用户确认后生成不可变价格版本并归档原文件。
6. 按 USD 档位或国家查看三渠道价格。

## 非功能要求

- 本地运行，默认不上传业务文件。
- 同一输入与基础数据应得到确定结果。
- 错误必须定位到文件、Sheet、行、列和原值（可取得时）。
- 数据库操作应事务化；失败不得留下半版本。
- 典型文件解析期间 UI 不假死，并显示进度。

## 不在 Phase1

汇率分析、调价建议、批量修改渠道、渠道 API、修改后校验以及新增渠道。

## 成功标准

三个渠道样本可导入；14 个档位可统一查看；坏数据无法进入活动版本；历史版本与原文件可追溯。

## Phase1 客户端体验基线

- 三个主入口使用左侧导航；页面右侧承载价格导入、价格库和版本管理。
- 导入检查左侧展示解析详情，右侧展示错误/警告；详情包含国家码、中文国家/地区名和渠道业务字段。
- 面向用户的调价方式、问题级别和问题说明使用中文，同时保留错误代码与来源定位。
- 2,500 条量级预览的国家/档位切换不应出现长时间“未响应”；筛选不得重复解析来源或重建全部单元格控件。
