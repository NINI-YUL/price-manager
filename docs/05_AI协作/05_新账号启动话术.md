# 新账号启动话术

以下内容可直接复制到新 ChatGPT/Codex 账号。推荐先使用第一段，只读核验通过后再使用第二段。

```text

本轮只恢复上下文和核验基线，不修改项目源代码或文档、不提交、不推送，也不开始 Phase2。测试与种子幂等验证只能使用临时数据库或 Git 已忽略的运行目录。

请依次执行：
1. 阅读仓库根目录 AGENTS.md。
2. 阅读 docs/00_项目管理/04_项目交接总览.md、01_项目状态.md、03_设计决策记录.md。
3. 阅读 PRD、业务规则、数据字典、测试验收标准、AI 开发协作规则，以及 P1-004～P1-009 执行说明中的验收结果。
4. 检查 git status、当前分支、HEAD、origin/main 和最近提交。
5. 运行现有测试、Ruff、种子初始化两次和 Qt smoke test；不要修改真实 Excel。
6. 报告：已完成任务、下一阶段、代码/文档是否一致、测试结果、数据库 schema/国家/档位数量、外部样本是否可用，以及 Phase2 是否已有确认规则、执行说明和明确开始授权。

已知基线：P1-001～P1-009 已完成；当前应有 115 项测试、schema v4、191 个国家/地区、14 个 USD 档位；P1-007 临时端到端回归为 Google 2,422、iOS 2,450、Web 420，合计 5,292 条和 3 个活动版本。P1-008 已完成只读价格库，P1-009 已完成版本管理与状态审计，Phase1 客户端验收整改已完成左侧导航、中文字段/问题、统一金额和快速筛选；正式数据库未写测试价格。Phase2 尚待确认。若实际结果不一致，请停止并列出证据，不要自行修复或覆盖。
```

## 话术四：防止继续无限补文档

```text
请先区分“阻塞当前开发的必需确认”和“可以边开发边补充的文档”。除非缺失信息会改变数据模型、解析规则、用户流程或验收结果，否则不要新增前置 Markdown 阻塞开发。优先完成当前已确认任务的小步实现、测试和真实样本验证；需要新增文档时，说明它解决的具体风险。
```

## 话术五：阶段结束时生成下一份交接快照

```text
请在当前任务验收后生成交接快照：记录完成提交、变更文件、实际测试结果、数据/样本哈希、已确认规则、遗留问题、下一任务边界和启动话术；同步更新 AGENTS.md、项目交接总览、项目状态和更新记录。快照必须让一个看不到本次聊天的新账号，仅凭仓库即可继续。
```
