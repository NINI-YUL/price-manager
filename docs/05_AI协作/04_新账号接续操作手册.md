# 新账号接续操作手册

更新时间：2026-08-19

## 推荐方案

最稳妥的交接顺序是：

1. GitHub `main` 保留代码、测试和项目文档，作为唯一真相源。
2. 新账号在 Codex 中打开同一台电脑的正式目录，或用 GitHub Desktop 克隆到新电脑。
3. 把本项目创建为新账号中的独立 Project，并粘贴启动话术。
4. Google/iOS/Web 原样本仅在回归已完成任务时重新提供；所有真实文件继续保留在 Git 之外。
5. 旧聊天可通过共享 Project 或导出 JSON 作为辅助参考，但不得替代仓库文档和测试。

## 方案 A：同一台电脑继续

1. 新账号登录 Codex。
2. 打开目录 `E:\项目管理\渠道价格管理工具`。
3. 确认 GitHub Desktop 仍能看到 `NINI-YUL/price-manager`，当前分支为 `main`。
4. 在新任务中粘贴 `05_新账号启动话术.md` 的“首次接手只读核验话术”。
5. 让新账号先读取 `AGENTS.md` 和交接总览、运行核验，不立即改代码。
6. 核验结果正确后，读取 `docs/03_开发设计/20_P1-009版本管理执行说明.md` 与 `21_Phase1客户端验收整改执行说明.md` 的完成记录；Phase2 尚未确认，不自行编码。

ChatGPT/Codex 账号和 GitHub Desktop 登录是两套独立凭据。更换 ChatGPT 账号不要求更换 GitHub 仓库，也不需要安装 `gh`；继续使用现有 GitHub Desktop 凭据即可。

## 方案 B：换电脑继续

1. 安装 GitHub Desktop，并登录拥有 `NINI-YUL/price-manager` 权限的 GitHub 账号。
2. 克隆 `https://github.com/NINI-YUL/price-manager.git`。
3. 安装 Python 3.11+，按交接总览创建 `.venv`、安装依赖并运行验收命令。
4. 将 Google Excel、iOS 原始 CSV 目录与 Web Excel 单独安全复制到新电脑；不得放进仓库。
5. 用交接总览中的摘要确认原始材料未发生变化。
6. 登录新 ChatGPT/Codex 账号，打开新克隆目录并执行首次只读核验话术。

## 旧 ChatGPT 上下文的两种可选迁移方式

### 方式 1：共享原 Project

如果原账号仍可访问，可在原 Project 中使用 Share 邀请新账号。共享 Project 可以让成员看到项目内的聊天、文件和说明，并在同一项目上下文中继续；共享后使用项目专属记忆。共享前应检查项目中是否包含不应向新账号暴露的文件或信息。

[ChatGPT Projects 官方说明](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)

### 方式 2：导出会话 JSON

个人 ChatGPT 账号可从设置中导出数据，在 ZIP 中找到 `conversations.json`，再上传到新账号的新对话作为参考。此方式不会合并账号，不会重建原聊天侧边栏，也不会转移订阅、记忆、设置、GPT、文件或工作区权限。

[跨账号使用已导出会话的官方说明](https://help.openai.com/en/articles/9106926)

本项目不依赖这一步才能继续；仓库中的交接文档已经包含后续开发所需的稳定上下文。

Project instructions 可粘贴：

```text

```

## 每个任务的固定交付节奏

1. AI 只读核验当前状态。
2. AI 说明任务范围、文件、测试和待确认项。
3. 负责人明确确认开始。
4. AI 实现当前任务并运行自动测试。
5. AI 更新状态、更新记录和对应执行说明。
6. AI 检查 diff，仅提交当前任务文件。
7. 同步本地正式目录、最新版 ZIP 和 GitHub `main`。
8. AI 停止，等待负责人确认下一任务。
