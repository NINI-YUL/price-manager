|ADR-002|采用 Python、PySide6、SQLite|生态成熟，适合桌面与 Excel 处理|已确认|
|ADR-003|每个渠道使用独立 Adapter|隔离模板差异，便于扩展|已确认|
|ADR-004|页面不直接读取 Excel|解析、业务、存储和 UI 解耦|已确认|

|ADR-007|国家使用 ISO 3166-1 alpha-2；币种使用 ISO 4217|统一多渠道标识|已确认|
|ADR-008|基础数据初始化必须幂等|重复运行不得重复或破坏数据|已确认|
|ADR-009|Phase1 不引入汇率、调价和渠道 API|控制首版范围|已确认|
|ADR-010|Google Excel 按表头别名识别，不绑定列序号|提高模板兼容性|已确认|
|ADR-011|Phase1 国家范围和默认币种取自已确认 Google 样本，中英文显示名固定为 Unicode CLDR 48.2.0|与真实渠道范围一致，同时保证名称来源可追溯、可复现|已确认|
|ADR-012|基础数据冲突时失败并整体回滚，不自动覆盖|防止未经确认改变国家名称、币种或档位基线|已确认|
|ADR-013|Phase1 国家范围扩展为 Google 与 iOS 实际国家/地区并集 191 个；显示名继续使用 Unicode CLDR 48.2.0|支持两个已接入渠道并保持名称来源可追溯|已确认|
|ADR-014|iOS 每行的币种为该价格记录权威值；国家默认币种只作基础参考|同一国家在渠道价格文件中的实际币种不得被种子默认值覆盖|已确认|
|ADR-015|iOS 调价方式按行保存：`N=MANUAL`、`Y=AUTOMATIC`；Google/Web 可为空|文件名不能可靠代表每行状态，且用户需要后续查看|已确认|
|ADR-016|iOS 输入为 14 个档位子目录，每档两份固定名称 CSV；档位取目录名|与真实导出结构一致，避免从价格反推档位|已确认|
