# P1-002 数据库建立执行说明

## 任务边界

仅建立 SQLite 数据访问基础、6 张 Phase1 表、约束、索引和自动化测试。国家与 14 档数据由 P1-003 写入；不得开发导入 UI 或渠道解析。

## 文件建议

```text
src/database/
├── connection.py
├── schema.py
└── repositories/
tests/integration/database/
```

数据库默认位于 `data/price_manager.db`，测试使用临时数据库。

## 建表要求

表与字段以 `06_数据字典.md` 为准。连接建立后执行 `PRAGMA foreign_keys=ON`；DDL 使用 `CREATE TABLE/INDEX IF NOT EXISTS`。关键约束：

- 国家编码、版本号、任务号唯一。
- 商品映射 `(channel, product_id)` 唯一。
- 价格记录在版本内唯一，价格和档位必须大于 0。
- 渠道、版本状态、任务状态限定枚举值。
- 外键删除默认限制，避免误删历史数据。

SQLite 仅支持部分索引时，为每个渠道只保留一个活动版本建立唯一部分索引：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS ux_active_version_per_channel
ON price_versions(channel) WHERE status = 'ACTIVE';
```

## 执行步骤

1. 实现连接上下文，提交/回滚/关闭行为明确。
2. 实现 schema 初始化入口，并保证重复运行无副作用。
3. 建立 6 表和查询索引。
4. 提供最小 Repository 冒烟能力：插入、按键查询、事务回滚；不实现渠道业务。
5. 用临时数据库运行集成测试。

## 必测场景

- 首次初始化得到且仅得到 6 张业务表；再次初始化不报错。
- 外键生效；非法状态、负价格、重复键被拒绝。
- 事务异常后无半成品数据。
- 同一渠道不能存在两个活动版本，不同渠道可以。
- 测试不创建或污染正式 `data/price_manager.db`。

## 完成定义

所有 schema 测试通过；数据库可由程序自动创建；表、列、约束、索引与数据字典一致；countries 与 price_tiers 仍为空，交给 P1-003。
