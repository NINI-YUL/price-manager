# 系统架构说明

```text
PySide6 UI
   ↓ 调用
Application Services ── Import / Query / Version / Exchange Rate / Analysis
   ↓                ↘
Channel Adapters      Validation Rules
   ↓                      ↓
Excel files        Domain records/issues
          ↘          ↙
          Repositories
               ↓
             SQLite
```

## 依赖方向

UI 依赖服务接口；服务依赖 Adapter 与 Repository 抽象；渠道 Adapter 不依赖 UI 或数据库；数据库层不包含 Excel 规则。领域模型不反向依赖基础设施。

## 关键流程

1. UI 创建导入任务。
2. 对应 Adapter 读取文件并产生标准记录与问题。
3. 校验服务补充跨行、基础数据和唯一性检查。
4. UI 展示预览；阻断错误为零后接受确认。
5. P1-007 确认服务重新验证任务、来源摘要、警告与覆盖缩减门禁，准备来源归档后在单一 SQLite 事务中切换活动版本、写价格并关联任务。
6. 归档或数据库任一步失败时不产生半版本；孤立归档仅报告、不得自动删除。
7. P1-008 通过只读查询服务组合各渠道活动/历史版本，不修改价格或版本状态。
8. P1-009 查询版本统计与归档状态；手动启用在单事务中切换版本并写审计事件，随后按渠道刷新价格库。

## Phase2 汇率分析架构

- `ExchangeRateApiProvider` 隔离外部接口；`ExchangeRateService` 统一处理自动/手动获取、供应商更新时间去重、缓存、失败日志和快照持久化。
- schema v5 的汇率快照与获取日志独立于七张 Phase1 表；成功快照不可变，历史列表分页/按需加载。
- `PriceAnalysisService` 只读组合一个汇率快照与三个渠道各自选择的完整价格版本，使用 Decimal 动态计算理论价和偏差，不持久化分析结果。
- 汇率网络请求由后台工作线程执行；分析表使用按需取数模型和代理筛选，配置弹窗维护草稿并在确认时原子应用到当前分析视图。

## 扩展点

新渠道通过实现相同 Adapter 契约加入；汇率与调价作为独立服务，不修改原始价格记录。

## 客户端验收整改架构

- `ApplicationShell` 负责左侧导航和右侧页面栈，不承载业务写入。
- `ImportPage` 负责流程编排、摘要、问题与确认入口；后台线程继续调用渠道 Service。
- `PricePreviewTableModel` 只持有标准预览记录并按需提供显示值；`PricePreviewFilterProxyModel` 只处理国家/档位过滤。
- 中文国家名从只读基础数据 Repository 取得；加载失败不阻断客户端，国家码仍可显示。
- 问题代码与业务门禁属于领域结果，中文说明属于展示映射；翻译不得改变严重级别或确认逻辑。
