# P1-009 版本管理执行说明

版本：V1.0｜完成日期：2026-08-18｜状态：已完成

## 目标

在 P1-007 正式版本事务和 P1-008 只读价格库之上，提供独立版本管理页面，使用户能够查看活动与历史版本、核验来源归档、读取状态审计，并在二次确认后将历史快照重新设为当前活动版本。

P1-009 不编辑或合并任何历史价格，不提供版本删除和价格导出，不扩展到汇率、调价、渠道 API 或 Phase2/Phase3。

## 已确认业务规则

### 1. 页面与筛选

- 主导航新增“版本管理”，与“价格导入”“价格库”并列。
- 展示当前生效版本数、历史归档版本数和归档异常数。
- 支持版本号/来源文件搜索，以及渠道、状态、年份、月份筛选。
- ACTIVE 版本置顶；同组内按导入时间和版本号倒序。
- 列表显示版本号、渠道、状态、导入时间、来源文件、记录数、国家数、币种数、归档状态和操作。

### 2. 版本状态与历史启用

- 只保留 ACTIVE、ARCHIVED 两种状态。
- 每个渠道最多一个 ACTIVE 版本；页面不提供单独归档当前活动版本的入口。
- 允许重新启用 ARCHIVED 历史版本。启用时，当前 ACTIVE 自动变为 ARCHIVED，目标版本变为 ACTIVE。
- 两项状态变化和对应审计记录必须在同一个 BEGIN IMMEDIATE 事务中完成；任一步失败整体回滚。
- 状态切换不修改、不复制、不合并 channel_prices，历史价格快照保持只读。
- 不提供任何版本删除入口。

### 3. 二次确认

- 启用前展示当前版本与目标版本的版本号、导入日期、记录数、国家数、币种数和档位覆盖。
- 展示记录数、国家数和档位覆盖变化；覆盖减少时使用强提醒。
- 归档缺失、摘要不一致或 ZIP 损坏时显示明显警告，但不阻止切换，因为数据库中的正式价格快照仍可完整启用。
- 用户必须勾选确认框后才能提交；操作备注可选，最多 200 字。

### 4. 状态审计

schema 从 v3 升级为 v4，新增 version_status_events：

- event_id：唯一事件编号。
- version_id、channel：目标版本及渠道。
- from_status、to_status：状态变化。
- replaced_version_id：本次相互替换的版本。
- reason：IMPORT_CONFIRMATION、MANUAL_ACTIVATION 或 MIGRATION_BASELINE。
- note：可空操作备注，最大 200 字。
- actor：本地单用户环境固定为 LOCAL_USER。
- created_time：带时区 ISO 8601 时间。

v3 及更早数据库升级时，为每个既有版本补一条 MIGRATION_BASELINE，只记录升级时可确认的当前状态，不伪造升级前的历史操作。以后 P1-007 导入确认和 P1-009 手动启用均在原业务事务中写审计事件。

### 5. 版本详情与价格库联动

- 详情展示版本、渠道、状态、导入时间、记录/国家/币种/档位数、来源、摘要、关联任务和任务状态。
- “状态记录”展示事件时间、原因、状态变化、替换版本、备注和操作人。
- “在价格库查看”切换到 P1-008，并只替换目标渠道的版本选择；其他渠道选择保持不变。
- 手动启用成功后，价格库对应渠道自动指向新的 ACTIVE 版本，版本管理页面刷新，其他渠道不变。

### 6. 来源归档

- price_versions.source_file 继续保存 archives 根目录下的相对路径；任何越界路径均拒绝访问。
- Google/Web：计算归档文件 SHA-256，并与 source_sha256 比较。
- iOS：执行 ZIP 结构和 CRC 完整性检查；数据库中的 source_sha256 是原始目录规范摘要，不与 ZIP 文件摘要直接比较。
- 详情显示路径、大小、修改时间和检查说明。
- 支持打开归档所在文件夹，不自动打开 Excel 或 ZIP，不复制、不删除归档。

## 服务与错误语义

|代码|含义|
|---|---|
|V001|版本列表或详情读取失败|
|V002|目标版本不存在|
|V003|目标版本已经是活动版本|
|V004|操作备注超过 200 字|
|V005|状态事务或审计写入失败，已回滚|
|V006|归档目录不存在或系统无法打开|

## 数据库与事务

- schema v4 共 7 张业务表。
- version_status_events(version_id, created_time) 和 (channel, created_time) 建立索引。
- 事件通过版本/渠道组合外键关联 price_versions，替换版本也受外键约束。
- v1/v2/v3 → v4 迁移保持原子、幂等；迁移失败不提高 user_version。
- 正式导入创建新版本时记录新版本 NULL → ACTIVE；存在旧活动版本时同时记录旧版本 ACTIVE → ARCHIVED。
- 手动启用记录目标 ARCHIVED → ACTIVE 和原活动版本 ACTIVE → ARCHIVED。

## 页面实现

- VersionManagementPage：统计、筛选、版本表、详情、归档操作和重新启用入口。
- VersionDetailDialog：版本概览、来源归档、状态事件及价格库跳转。
- VersionActivationDialog：版本差异、归档警告、备注和强制确认。
- ApplicationShell：三项主导航；确认导入刷新版本页；手动启用和详情跳转均只更新价格库对应渠道。

## 自动化验收

- Schema：v4 幂等初始化、索引、v1/v2 兼容及 v3 基线事件。
- Repository/服务：统计查询、文件 SHA-256、iOS ZIP、缺失/越界归档、手动启用、导入审计、审计失败回滚和备注限制。
- UI：统计、搜索、渠道/状态/年月筛选、无删除/导出入口、详情、确认勾选、启用刷新、三页面导航和价格库单渠道联动。
- 测试只使用临时数据库和临时归档，不向正式数据库写入测试价格。
