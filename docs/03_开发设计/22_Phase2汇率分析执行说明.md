# Phase2 汇率分析执行说明

版本：V1.6｜日期：2026-08-25｜状态：正式通过客户端验收，v0.1.1 补丁已归档

## 一、目标与阶段边界

Phase2 在 Phase1 已验收的不可变价格版本之上增加汇率快照和只读价格偏差分析。分析用于判断渠道实际本地价格相对统一 USD 档位和市场参考汇率的偏高、偏低程度，不用于财务结算、渠道改价或交易执行。

本说明是 Phase2 唯一执行基线。负责人已明确授权开始开发；本次实现只新增独立汇率快照、获取日志和只读分析，不扩展到 Phase3。

## 二、统一术语

- **价格版本**：Phase1 已确认入库的渠道完整价格快照，状态为 `ACTIVE` 或 `ARCHIVED`。
- **汇率快照**：ExchangeRate-API 在一个供应商更新时间返回的、以 USD 为基准的一整组汇率；保存后不可修改。
- **理论本地价格**：USD 档位按所选汇率快照折算得到的本地币种价格。
- **价格偏差**：实际本地价格相对理论本地价格的差异。该结果可能同时受到税费、定价尾数和渠道策略影响，不称为纯粹的“汇率误差”。
- **选择历史版本**：仅将 `ARCHIVED` 价格版本用于只读分析，不等于通过 P1-009 重新启用该版本。

## 三、已确认业务规则

### 3.1 汇率来源

1. Phase2 主汇率源固定为 ExchangeRate-API 免费开放接口：`https://open.er-api.com/v6/latest/USD`。
2. 汇率仅用于信息展示和价格偏差分析，不作为财务结算或真实交易汇率。
3. 界面按供应商要求展示来源署名。
4. 不自动拼接或混用其他供应商的汇率；如主来源未来停止服务、缩减币种或改变许可，另行确认替代来源。
5. 当前已确认 Google 原样本实际出现 61 种币种，接口当前覆盖全部 61 种；运行时仍必须根据实际价格记录校验币种是否存在。

### 3.2 基准币种与换算方向

1. 基准币种固定为 `USD`。
2. 汇率方向固定解释为：`1 USD = R 单位本地币种`。
3. 理论本地价格按 `USD 档位 × API 汇率`计算。
4. 必须使用 `channel_prices.currency` 中价格记录自身的币种，不得以 `countries.default_currency` 替代。
5. 不经过 EUR 或其他中间币种二次换算；`USD` 的汇率固定为 `1`。

### 3.3 汇率时间点与不可变快照

1. 默认使用接口返回的最新汇率。
2. 汇率生效时间以响应中的 `time_last_update_utc` 为准；本机成功请求时间单独记录为获取时间，不得冒充汇率生效时间。
3. 同一次响应中的全部币种构成一个完整快照，不得逐币种混合不同供应商时间的数据。
4. 以“供应商 + USD 基准 + `time_last_update_utc`”唯一标识快照；同一供应商更新时间最多保存一份。
5. 成功快照不可变、永久保留且不自动清理；重复响应不新增快照。
6. 历史快照按日期按需读取，不一次性加载全部汇率明细。
7. ExchangeRate-API 免费接口不提供任意历史日期回查，因此历史快照从 Phase2 首次成功获取后开始积累，不伪造或补猜上线前历史汇率。
8. 一次分析统一绑定一个汇率快照；分析期间不得被后台新快照静默替换。

### 3.4 自动获取、手动获取与失败回退

1. 工具未启动时不获取汇率；不得创建 Windows 后台服务或系统计划任务。
2. 首次使用且本地没有成功快照时立即获取。
3. 后续自动获取时间由上一响应的 `time_next_update_utc` 决定，在该时间后延迟 10 分钟执行。
4. 应用关闭期间不运行；下次启动或进入汇率分析页时，如已超过下一更新时间，则立即补取。
5. 页面提供“获取最新汇率”按钮。请求进行期间按钮禁用，防止并发重复请求。
6. 自动和手动请求使用同一快照唯一规则：返回新供应商时间时保存新快照；返回已有时间时提示“当前已是最新汇率”，不新增数据。
7. 正常情况下免费接口每日更新一次，因此实际约每日保存一个快照；如果供应商在同一天产生第二个不同更新时间，允许保存第二个真实快照。
8. 打开页面时先使用本地最新成功快照，不等待网络请求阻塞界面。
9. 网络超时、HTTP 错误、限流、业务响应失败、响应结构错误、基准币种不是 USD、时间字段无效或汇率非正数均视为获取失败，不保存成功快照。
10. 获取失败且已有成功快照时继续使用最近快照，明显显示“正在使用缓存”、汇率生效时间和距今天数；没有任何成功快照时不计算理论价格或偏差，只显示“暂无可用汇率”并允许重试。
11. 成功快照超过 24 小时标记“汇率已过期”；超过 7 天仍允许只读查看和计算，但必须显示醒目警告，不得静默当作最新汇率。
12. 当前快照缺少某条价格记录的币种时，仅该记录显示“汇率缺失”，不得从旧快照借用单个币种补齐。
13. 获取失败日志与成功快照分开管理；失败日志保留最近 90 天后可自动清理，成功快照不受影响。

### 3.5 价格版本与汇率快照选择

1. Phase2 默认使用 Google、iOS、Web 各自当前 `ACTIVE` 价格版本。
2. 允许三个渠道分别选择任意 `ACTIVE` 或 `ARCHIVED` 版本；每个渠道一次只选择一个完整价格版本。
3. 选择历史价格版本只用于分析，不改变版本状态，不写入 P1-009 状态审计。
4. 不合并同渠道多个版本，也不从其他版本补齐缺价。
5. 三个渠道可选择不同导入时间的价格版本，但一次分析中的所有渠道必须统一使用同一个汇率快照。
6. 汇率快照默认选择最新成功快照；用户可明确选择已保存的历史快照回看过去。
7. 不自动为三个渠道分别匹配各自价格版本导入日期的不同汇率，否则会破坏同一分析中的时间可比性。

### 3.6 价格偏差公式

对每条价格记录定义：

```text
U = USD 档位
R = API 汇率（1 USD = R 本地币种）
T = 理论本地价格 = U × R
A = 实际本地价格

本地价格差额 = A − T
价格偏差率 = (A − T) ÷ T × 100%
```

等价的辅助解释为：

```text
渠道隐含汇率 = A ÷ U
价格偏差率 = (渠道隐含汇率 − R) ÷ R × 100%
```

1. 正偏差表示实际本地价格高于理论价格，负偏差表示实际本地价格低于理论价格。
2. 预警分级使用偏差率绝对值，但界面保留正负号和“偏高/偏低”方向。
3. 价格、汇率及全部中间计算使用 `Decimal`，不得使用二进制浮点数。
4. 中间结果不提前舍入；阈值判断使用未舍入的完整偏差率，不使用界面舍入值。
5. 使用数据库中实际保存的完整本地价格精度；iOS `MANUAL/AUTOMATIC` 属性不改变计算公式。
6. 缺少对应币种汇率时不计算偏差。
7. 不自动扣除税费、渠道佣金或支付手续费，因为现有正式数据没有可靠字段支持这些调整。

### 3.7 展示精度与预警阈值

1. USD 档位固定显示两位小数。
2. 实际本地价格沿用 Phase1 规则：整数不带小数；一位或两位有效小数统一显示两位；超过两位有效小数保留原值并提示。
3. API 汇率最多显示 3 位小数，去除无意义末尾零，不使用科学计数法；该显示值不参与计算。
4. 理论本地价格与本地价格差额显示两位小数，差额保留正负号。
5. 价格偏差率显示两位小数并保留正负号；所有派生值仅在展示时四舍五入。
6. 预警阈值固定为：

|价格偏差率绝对值|状态|
|---:|---|
|`< 10%`|正常|
|`>= 10% 且 < 20%`|关注|
|`>= 20%`|显著偏差|

7. 恰好 `10%` 进入“关注”，恰好 `20%` 进入“显著偏差”。正负偏差使用相同绝对值阈值。
8. 汇率缺失、快照过期和获取失败是独立状态，不计入价格偏差等级。
9. Phase2 不复用 Phase1 导入检查的 `ERROR/WARNING` 术语，避免误解为入库阻断。
10. 首版阈值固定，不增加系统设置；如真实使用证明阈值需要调整，再单独确认。

### 3.8 Phase2 只读边界

1. Phase2 是只读分析阶段，对既有价格、价格版本和版本状态完全只读。
2. 不得修改 `channel_prices`、`price_versions`、`version_status_events`、`import_tasks`、`countries`、`price_tiers` 或 `channel_products`。
3. 只允许新增及读取 Phase2 独立的汇率快照和获取日志。
4. 理论价格、差额、偏差率和预警等级均动态计算，不反写价格库，也不保存为新的正式价格。
5. 偏差等级只用于展示、筛选和统计，不阻断、不归档、不启用任何价格版本。
6. 不创建调价任务，不提供调价建议或修改校验，不调用 Google、iOS、Web 渠道 API。
7. 不提供价格导出；价格导出仍是需要单独确认的任务。

## 四、数据与实现约束

Phase2 开发时允许通过受测迁移新增独立汇率数据结构，但不得改变七张 Phase1 业务表的既有语义或绕过其服务边界。

汇率快照至少需要表达：供应商、基准币种、供应商生效时间、供应商下一更新时间、本地获取时间、完整币种汇率集合和唯一约束。汇率值按十进制精度保存。

获取日志至少需要表达：请求时间、自动/手动触发方式、结果状态、可读错误信息和关联快照（如成功）。失败日志清理不得级联删除成功快照。

分析结果能够由“明确的价格版本组合 + 一个汇率快照”确定性重算，因此首版不持久化分析结果。

6. 无价格版本、无汇率快照、币种汇率缺失、缓存过期、获取失败和无筛选结果的明确空状态。
