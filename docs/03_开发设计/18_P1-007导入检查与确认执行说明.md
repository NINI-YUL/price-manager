# P1-007 导入检查与确认执行说明

版本：V1.1｜完成日期：2026-08-17｜状态：已完成

## 目标

在三个已完成渠道 Adapter 的统一预览模型之上，实现可实际使用的“选择渠道/来源 → 解析 → 检查 → 确认入库”流程。只有无阻断错误并经用户明确确认的预览，才生成正式价格版本。

P1-007 包含导入页、检查页、确认服务、正式事务、源文件归档和对应测试；价格库查询页属于 P1-008，版本管理页属于 P1-009。

## 已确认业务规则

### 1. 检查与编辑边界

- `ERROR` 一律阻断，“确认入库”按钮禁用。
- 只有 `WARNING` 时允许入库，但必须弹出二次确认并展示警告数量。
- 状态为 `FAILED` 的任务不能确认，只能修正来源后重新解析。
- 接受记录数必须大于 0。
- 检查页不直接编辑解析后的国家、档位、币种或价格；发现错误必须修改原文件后重新导入，避免预览与来源文件不一致。

### 2. 完整快照与覆盖缩减

- 每次确认导入都生成该渠道的完整新快照，不与旧活动版本合并，也不静默沿用旧价格。
- Web 文件可以只覆盖 191 个基础国家/地区中的实际经营子集；这仍视为 Web 渠道自身的完整快照。
- 已有活动版本时，若新预览的国家数或记录数减少，显示强提醒并要求二次确认；用户不确认则不入库。
- 新活动版本生效后，旧活动版本整体归档。

### 3. 版本规则

- 版本号格式固定为 `{CHANNEL}_VYYYYMMDD_NNN`。
- 日期使用运行电脑的带时区本地日期；序号按渠道和日期分别从 `001` 递增。
- 版本号分配、旧版本归档、新版本创建、价格写入和任务成功更新在同一数据库事务内完成。
- 每个渠道最多一个 `ACTIVE` 版本，历史版本只读保留为 `ARCHIVED`。

### 4. 重复来源

- 若同一渠道、相同 `source_sha256` 已经成功生成过任一正式版本，则阻止再次入库，并显示已有版本号。
- 仅解析失败、尚未确认或确认失败的任务不算正式重复，允许重新解析和确认。
- 重复判断不受已有版本当前是 `ACTIVE` 还是 `ARCHIVED` 影响。

### 5. 原文件归档

- 归档采用复制，不移动、不修改用户原文件。
- Google/Web 原始 `.xlsx` 原样复制；iOS 完整目录打包为 ZIP。
- 归档目录为 `archives/{channel}/{version_id}/`，`price_versions.source_file` 保存归档后的相对路径。
- 正式确认前重新计算来源摘要，必须与预览摘要一致；不一致时要求重新解析。
- 先在临时位置准备并校验归档，再执行确认事务；归档失败不得创建正式版本。
- 数据库事务失败时删除本次新建归档；异常退出留下的无版本孤立归档在下次启动时只报告、不自动删除。

### 6. 预览生命周期

- P1-007 的预览明细只保存在当前程序会话内，不新增临时价格表或问题表。
- 关闭程序后未确认预览不可恢复，用户需要重新选择来源并解析。
- 确认服务必须校验预览渠道、来源路径、SHA-256、任务号和任务状态，防止确认过期或错配预览。

## 页面范围

### 导入区

- 渠道单选：Google、iOS、Web。
- Google/Web 使用文件选择器；iOS 使用目录选择器。
- 展示来源路径、文件或目录摘要、解析状态和进度。
- 解析过程中禁用重复启动；解析完成后进入统一检查区。

### 检查区

- 摘要：渠道、国家数、币种数、档位数、接受价格数、错误数、警告数，以及 iOS 手动/自动调价数量。
- 问题表：级别、代码、Sheet/文件、行、列、原值和说明。
- 价格预览：国家代码、USD 档位、币种、本地价格、商品 ID、调价方式和来源定位。
- 支持按国家、档位和问题级别筛选；筛选不改变实际待确认记录集合。
- 提供“重新选择”“重新解析”“确认入库”操作。

## 确认服务流程

1. 校验任务存在且为 `CHECKING`，预览属于该任务和渠道。
2. 校验接受记录非空、无 `ERROR`；存在预览警告时要求显式确认标记。
3. 重新计算来源 SHA-256 或 iOS 目录规范摘要，确认来源未变化。
4. 检查同渠道相同摘要是否已有正式版本；存在则阻止并返回已有版本号。
5. 读取当前活动版本并计算国家数、记录数差异；缩减时要求显式确认标记。
6. 在临时位置复制/压缩来源并校验归档。
7. 使用 `BEGIN IMMEDIATE` 开始事务并再次检查任务状态、重复摘要和活动版本。
8. 生成版本号，先将旧活动版本置为 `ARCHIVED`，再创建新 `ACTIVE` 版本。
9. 批量写入 `channel_prices`；Google 同步新增或核对 `channel_products` 映射，既有商品映射冲突则整体失败。
10. 将任务置为 `SUCCESS`，写入关联 `version_id` 和完成时间后提交事务。
11. 任一步失败则回滚全部数据库变化，清理本次归档，任务保持 `CHECKING` 并显示可重试错误。

UI 的二次确认不能替代服务层参数；确认服务必须显式收到“接受普通警告”和“接受覆盖缩减”标记，防止其他调用路径绕过门禁。

## 数据库变更

schema 从 v2 升级为 v3：

- `import_tasks` 新增可空 `version_id`，引用 `price_versions.version_id`。
- 为非空 `import_tasks.version_id` 建立唯一索引，保证一个正式版本只关联一个导入任务。
- 为 `price_versions(channel, source_sha256)` 建立查询索引，加速重复来源检查。
- 既有任务的 `version_id` 保持 `NULL`；迁移必须原子、幂等，失败整体回滚。
- `completed_time` 在确认成功时记录；确认失败或用户取消时任务保持 `CHECKING`。

不新增预览明细表、问题表或额外业务表。

## 事务与数据写入

- `local_price`、`usd_tier` 继续使用 `Decimal`，写库时保持十进制文本语义。
- `channel_prices` 只写 Adapter 已接受并去重后的记录。
- Google 的 `product_id` 不写入价格表，继续通过 `channel_products(channel, product_id, usd_tier)` 保存稳定映射。
- iOS 的 `adjustment_mode` 原样写入；Google/Web 保持 `NULL`。
- `record_count` 必须等于本版本实际写入的价格行数。
- 事务提交后重新读取版本、任务和写入行数作为服务返回结果。

## 自动化测试

### schema 与 Repository

- v2→v3 原子、幂等迁移，既有数据不丢失。
- 任务关联版本、每渠道单活动版本、重复任务版本关联和外键约束。
- 版本号按渠道/日期递增，跨渠道互不影响。

### 确认服务

- 三渠道首次确认成功，任务变为 `SUCCESS`，版本为 `ACTIVE`，行数与预览一致。
- 第二次确认归档旧活动版本并完整替换，不合并旧记录。
- `ERROR`、空预览、普通警告未确认、覆盖缩减未确认、来源变化和重复摘要均被拒绝。
- 普通警告和覆盖缩减分别确认后可继续。
- Google 商品映射新增、一致重用和冲突回滚。
- 写入中途、版本切换、任务更新或归档失败时无半版本、无半价格、无错误活动版本。
- Google/Web 文件复制与 iOS 目录 ZIP 归档成功；原始来源摘要保持不变。

### UI

- 三种渠道选择器使用正确的文件/目录模式。
- 解析状态、摘要、问题、预览和筛选正确展示。
- 有错误、任务失败或零记录时确认按钮禁用；仅警告时触发二次确认。
- 后台解析期间界面不重复启动任务；关闭未确认预览后要求重新解析。
